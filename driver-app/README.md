# AzBerry — تطبيق السائق (Flutter)

تطبيق مستقل للسائقين، يشارك نفس مشروع Supabase. لون مميّز (تركوازي) لتمييزه عن تطبيق الزبون.

## المزايا
- 🔐 تسجيل دخول للسائقين فقط (يُرفض أي حساب غير مسجّل كسائق).
- 🟢/⚪ مفتاح **متصل / غير متصل** (Online/Offline).
- 📋 **الطلبات المتاحة** في فرع السائق + زر **قبول الطلب** (يخصّص الطلب للسائق).
- 🚴 **تفاصيل الطلب**: الفرع، الزبون، العنوان، المبلغ، طريقة الدفع، الملاحظات + زر اتصال.
- 🔄 تحديث الحالة: «استلمت الطلب — بالطريق» ثم «تم التسليم».
- 📊 **ملخّص اليوم**: عدد الطلبات، الأرباح، المبلغ النقدي المحصّل.

## التشغيل
```bash
flutter pub get
flutter run           # جهاز/محاكي
# أو للويب:
flutter run -d chrome
```

## حساب اختبار
```
driver1@test.com / Test#1234   (سائق فرع بغداد - الكرادة)
```
> حسابات السائقين تُنشأ بترقية مستخدم موجود من لوحة التحكم (صفحة السائقين).

## البنية
```
lib/
  core/       config, theme, utils
  data/       models.dart, driver_repository.dart
  features/   login_screen, home_screen, order_detail_screen
  providers.dart
```

## RLS المستخدمة (مضافة في migration driver_app_policies)
- `orders_driver_claim`: يسمح للسائق بتخصيص طلب غير مُسنَد في فرعه لنفسه.
- `addresses_driver_read` / `users_driver_read_customer`: قراءة عنوان الزبون واسمه/هاتفه للطلب المُسنَد.
- تحديث الحالة عبر `orders_driver_update`، والموقع عبر `drivers_update_self`.

## يحتاج إعداداً أصلياً (خارج الكود)
- **GPS/الخريطة**: إرسال الموقع لحظياً وعرض خريطة الوجهة يتطلب `geolocator` + `google_maps_flutter` + مفاتيح ومنح أذونات (مرحلة لاحقة). الدالة `updateLocation` جاهزة في المستودع.
- **إشعار صوتي للطلب الجديد** + **الاتصال بالزبون**: يتطلبان حزمًا أصلية.

## تم التحقق
`flutter analyze` → No issues، `flutter build web` → نجح، وتدفّق «توفّر → قبول → بالطريق → تسليم» مُختبَر فعلياً عبر RLS بحساب السائق.
